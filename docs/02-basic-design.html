Section 01

システム構成

1.1 全体アーキテクチャ

本サイトはサーバーサイド処理を持たない純粋な静的サイトである。ビルドツール・バンドラー不使用。HTML/CSS/JSファイルを GitHub Pages から直接配信する最もシンプルかつ高速な構成を採用。
レイヤー技術役割

スタイリングCSS3 (Cascade + Custom Properties)デザイントークン・レイアウト・アニメーション
インタラクションVanilla JS (ES5 互換)スクロール検知・アニメーション・フォームUI
フォントGoogle Fonts CDNNoto Sans JP / Poppins / Cormorant Garamond
アイコンインラインSVG追加HTTP不要・style変更可能

  • ハンバーガーボタン (#hamburger) クリックで .is-open クラストグル

  • ドロワー表示中は body.overflow: hidden でスクロールロック
  • ドロワー内リンクをタップ → 即時クローズ + スムーズスクロール
Section 07

アニメーション基本設計

設計哲学：ポケモン株式会社サイトに代表される世界最高峰の日本語コーポレートサイトは「動きで驚かせない」。目的は「ユーザーを自然に次のコンテンツへ誘導すること」。アニメーションは情報の優先度と連動する。

7.1 アニメーション階層

層種別ファイル説明
Layer 0ページロードcss/animations.css + js/animations.jsカーテンが上に滑り出てページ露出（0.75s）
Layer 1Hero常時アニメーションcss/hero.css (keyframes)パーティクル・ブロブ・テキストフェードイン
Layer 2スクロールフェードcss/style.css + js/main.js.js-fade → .is-visible (opacity + translateY)
Layer 3スタガーcss/animations.css + js/animations.js.js-stagger-item を130ms間隔で表示
Layer 4インタラクションcss/animations.css + js/animations.js磁石ボタン・3Dティルト・カスタムカーソル
Layer 5UI Micro-animationcss/sections.css + hero.cssホバー変化・ナビ下線・チップスケール

7.2 アニメーション実行タイムライン（ページロード）

0ms
ページロードカーテン表示
#page-reveal が画面全体を覆う（濃紺）

8.2 タッチデバイス考慮事項

  • (pointer: coarse) 検知時、カスタムカーソル・磁石ボタン・3Dティルトを無効化
  • タップターゲット最小サイズ 44×44px 確保
  • スクロールイベントは { passive: true } で登録（iOS対応）
  • ドロワーメニュー閉じた後 body.overflow: '' で戻す
Section 09

パフォーマンス設計

9.1 ロードパフォーマンス最適化

施策実装方法効果
フォント最適化rel="preconnect" + display=swapFOUT 短縮、LCP 改善
CSSモジュール分割ページ固有CSS (services.css) は services.html のみロード不要CSS 削減
SVGインラインアイコンはHTMLにインライン記述HTTP リクエスト削減
パーティクル最適化particle数 = min(width*height/12000, 110)低スペック端末への配慮
IntersectionObserverビューポート外要素は animate 実行しないJank・再描画抑制
will-changeアニメーション要素に will-change: transformGPU合成レイヤー化
passive scroll全 scroll listener に { passive: true }スクロール応答性向上

9.2 Jank（カクつき）防止策

  • CSS アニメーションは transform・opacity のみ変更（layout/paint を発生させない）
  • JS でのスタイル変更は requestAnimationFrame 内で実行
  • カーソル追従は rAF ループで interpolate（lerp coefficient: 0.14）
  • 視差スクロール要素は親の getBoundingClientRect() を使用（scroll 毎は最小限に）
